# 影库 Windows 开发规则

基线：Windows v2.8.2，由 Mac v2.8.1 适配。源码运行入口 `windows_entry.py`，核心 UI `desktop.py`，数据层 `app.py`。

- 完整项目上下文见上级 `03-开发文档/开发接续说明.md` 和 `项目结构.md`。不要依赖之前的聊天来判断代码状态。
- Windows 10/11 x64，Python 3.12 x64。依赖用 `requirements-windows-lock.txt`，构建显式指定 `YingKu-Windows.spec`。
- 修改前检查现有变更；用户影片、资料库、API 密钥及缓存不是代码资产，不提交进版本库或交付运行版。
- 测试运行 `.venv/Scripts/python.exe scripts/run_tests.py`，自动使用临时数据。不得用真实资料库运行测试、静默删除影片或覆盖已有备份。
- 数据迁移须可重复执行并保留个人评分、收藏、备注、播放次数、演员资料和选中头像；跨平台路径不猜测。
- 分区隔离、系统验证、取消进入普通模式、一次验证持续到退出，以及标题点击切换都要保留。禁止添加跳过系统验证的环境变量或发行版测试后门。
- Windows Hello UI 绑定已有 Qt 窗口。回退凭据必须验证当前用户 SID。不要存储或打印密码 / PIN；取消不得继续提示其他验证方式。
- `process_utils.process_alive` 在 Windows 不使用 `os.kill(pid, 0)`。重启、还原操作要等旧进程正常结束，不终止其他应用。
- 后台结果通过 `TaskRunner` 回到主线程，图片管理器随主窗口关闭停止；不得让短生命 QRunnable 持有回调 QObject。
- 未确认的公开资料和图片不得编造，不用同名条目顶替。网络失败保留已取得的资料与收藏。
- Mac 原生组件只在 Mac 分支执行。Windows 播放跟随系统默认播放器，不尝试绕过系统默认应用保护。
- 运行适合变更的回归；平台特定测试按平台条件跳过，不把模拟通过说成真实生物识别已验证。
- 发布时更新 `VERSION`，运行测试、图标构建和 PyInstaller，检查 exe 的版本与 PE 架构，验证隔离启动，分发整个 `dist/影库`。
