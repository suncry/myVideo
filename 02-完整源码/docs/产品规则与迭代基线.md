# 影库产品规则与迭代基线

本文是继续迭代时的产品基线。新增功能可以扩展它，但不应在没有明确决定的情况下破坏这些规则。

## 1. 产品定位

- 影库是原生 Windows 桌面客户端，不依赖浏览器运行。
- 影片文件留在用户原来的硬盘、盘符和目录中；数据库只保存索引、匹配资料和个人整理状态。
- 核心目标是：汇总本地影片、自动补全资料、按演员和喜好检索、帮助用户判断保留或删除。
- 本地资料、评分和观看记录默认不上传。

## 2. 扫描源与自动同步

- 扫描源是用户明确添加的硬盘或文件夹，属于低频管理功能。
- 每次应用启动都检查所有已管理扫描源：
  - 新发现的支持格式影片自动入库。
  - 硬盘中确实不存在的影片从数据库移除。
  - 扫描源离线、目录无法读取或单个文件暂时不可读时，不得误删记录。
- 默认过滤 10 分钟以下内容；阈值可在扫描源管理中设置，并在每次启动时复查。
- 移除扫描源会删除该来源对应的影库记录和个人标记，但不会删除硬盘影片。

## 3. 隐藏与恢复

- 默认在影片入库后使用 Windows 文件属性原地隐藏，绝不为了隐藏而移动影片。
- 支持两种方式：标准隐藏，以及隐藏属性加系统属性的加强隐藏。
- 影片不直接位于扫描源根目录时，隐藏影片的直接所在目录；扫描源根目录永远不能被隐藏。
- 必须记录由影库修改前的原始文件或目录属性。只有影库实际修改过的对象，影库才拥有恢复责任。
- 以下情况恢复原始属性：
  - 用户关闭隐藏功能并重新扫描。
  - 用户移除扫描源。
  - 目录中已没有任何仍在库中的影片。
- 原本就由用户隐藏的文件或目录，不得擅自恢复为可见。
- 隐藏不是加密。产品文案不能把 Windows 隐藏属性描述为安全加密。

## 4. 删除规则

- 隐藏后，删除入口必须在影库中易于发现；影片卡片和详情页都提供删除操作。
- 删除单部影片默认移到 Windows 回收站，不直接永久删除。
- 只删除选中的影片文件，不连带删除字幕、NFO、封面或同目录其他内容。
- 文件成功进入回收站后才更新数据库状态。
- 删除该目录最后一部入库影片后，恢复目录原始属性。

## 5. 影片资料匹配

- 匹配结果、来源、置信度、候选状态、失败状态和最后尝试时间必须持久化。
- 应优先使用本地 NFO 和本地封面，再尝试联网来源。
- 编号型影片只在编号唯一且完全一致时自动采用。
- 普通影片综合片名、原名、年份和候选差距；低置信度结果不得静默写入。
- “未找到”和“待确认”不能在每次启动时无限重复查询；手工强制操作不受自动重试周期限制。
- 所有联网失败都应保留已有资料。

## 6. 演员资料

- 搜索栏下方提供演员头像和姓名，可用于快速筛选影片。
- 尽量显示中文名，保留原名和别名用于匹配与检索。
- 演员卡显示参演影片数和其中被标记喜欢的影片数。
- 新演员出现后自动补全头像和资料，并将结果写入本地数据库。
- 顶部刷新只检查没有头像的演员；已有头像必须跳过，避免重复联网。
- 只有右键演员头像进入照片窗口，再选择“强制重新联网查找”时，才重新匹配已有头像。
- 强制刷新成功才替换，失败必须保留现有头像和姓名。
- 每位演员最多保存 50 张照片候选，用户可在右键窗口中切换当前头像。
- 更新期间在演员区显示当前演员、完成进度、更新数、未找到数和上一项结果。
- 收起时加载全部演员，单行横向滚动；展开时按宽度换行，最多五行，更多内容纵向滚动。
- 演员区不得把影片列表压缩到不可正常浏览的高度。

## 7. 搜索、筛选与个人整理

- 搜索支持片名、演员、标签和文件名。
- 演员、喜欢状态和评分区间是可组合的独立筛选条件。
- 选中演员后必须提供清除演员筛选的操作，也应支持重置全部筛选。
- 评分采用五颗星，点击即自动保存。
- 喜欢、观看状态、待处理状态和详情页编辑均自动保存，不设置额外“保存整理”按钮。
- 不保留“喜欢或不喜欢的原因”和个人标签编辑等已经确认的伪需求入口。

## 8. 影片详情与关键截图

- 详情顶部采用沉浸式封面；封面高度可调并持久化。
- 评分位于标题下方。
- 播放、打开目录、匹配、编辑、删除等主要操作保持紧凑排列。
- 关键截图位于标题区域之后，默认两排大图，目标是快速判断影片内容。
- 没有截图时，首次查看详情自动生成约 10 张本地关键帧；失败后停止自动重试，允许手工重试。
- 点击任意截图进入整组预览，支持界面箭头和键盘 `←`、`→`，并显示当前序号。
- 截图只缓存在本机，不上传。
- 文件信息区包含文件路径、大小、时长、播放次数、最近播放时间和入库时间。

## 9. 响应式布局与状态记忆

- 横屏比例：影片列表在左，影片详情在右。
- 竖屏比例：影片列表在上，影片详情在下。
- 横屏和竖屏分别保存窗口大小、屏幕位置、列表/详情分隔比例和详情封面高度。
- 用户手动调整后的布局优先，不应在启动后被默认值覆盖。
- 窗口底部用小字显示影片总数、容量、喜欢、待补全、待处理和重复统计，避免占用主浏览空间。

## 10. 数据与升级兼容

- 用户数据库默认位于 `%LOCALAPPDATA%\YingKu\film_library.db`。
- 升级必须使用增量数据库迁移，不能要求用户删除旧数据库。
- 发布包不得默认包含开发者真实数据库、影片路径、Token、图片缓存或个人评分。
- 测试和成品验证必须使用隔离的数据目录，禁止触碰真实影片库。
- 新版本至少完成：Python 编译检查、完整自动化测试、PyInstaller 构建、隔离数据库启动验证。

## 11. 继续迭代时的优先级

1. 数据和影片文件安全。
2. 已保存的匹配资料与个人整理不丢失。
3. 避免不必要的重复联网与错误匹配。
4. 保持影片浏览空间和详情可读性。
5. 再考虑视觉微调和附加功能。
