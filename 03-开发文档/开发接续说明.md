# 开发接续说明

## 基线与功能

本包从影库 Mac v2.8.1 的最新源码适配而来，Windows 版本号为 2.8.2。技术栈为 Python 3.12、PySide6 / Qt、SQLite 和随包 FFmpeg。没有依赖本机浏览器页面的桌面外壳。

已有：影片扫描、NFO 与封面、评分与收藏、播放统计、截图、搜索与过滤、横竖窗口和全屏、整体滚动与顶部筛选、普通/隐私分区、演员收藏及管理、公开资料与关键词、人物图集与作品图片预览、自定义 `<name>` 网页搜索、资料库备份与文件指纹关联。

Windows 适配集中于 `windows_auth.py`、`process_utils.py`、`windows_entry.py`，以及 `privacy.py`、`app.py` 中的平台入口。Windows Hello 使用桌面 HWND 绑定的系统接口；取消不能解锁。凭据回退同时验证登录令牌的 SID 与当前用户一致，不接受其他 Windows 账户，不保存凭据。

Windows 的播放器由系统文件关联决定，Mac 的 IINA 专用组件不会在 Windows 被调用。Windows 数据目录与开发源码的位置分离。进程等待使用 Windows 查询句柄，不用 Windows 上会产生终止行为的 `os.kill(pid, 0)`。

## 推荐迭代流程

在 `02-完整源码` 开发。先运行 `开发环境准备.bat`，再启动源码。修改前通过应用的「备份与文件关联」页面保存当前模式的备份，分区之间不要混用备份。禁止直接覆盖正在使用的数据库。

建立自己的 Git 仓库可执行：

```powershell
git init
git add .
git commit -m "Windows v2.8.2 baseline"
```

`.gitignore` 已排除环境、构建产物、资料库、缓存、密钥配置和日志。为每次变更建立分支，保留 `VERSION` 版本记录。开发工具可读取源码中的 `AGENTS.md` 获取项目规则；完整源码和测试不依赖此聊天上下文。

不要修改 exe 的 `_internal` 或 `.venv` 中的安装文件来迭代产品；修改源码后重建。外部资料接口按已确认的人物 / 作品编号关联，网络失败保留缓存，不使用重名人物顶替，不制造简介、图片或代表作。

## 使用测试资料库

源码默认连接真实 Windows 用户资料库。临时实验可在 PowerShell 中运行：

```powershell
$env:YINGKU_DATA_DIR = Join-Path $env:TEMP 'YingKu-development-library'
$env:YINGKU_SETTINGS_PATH = Join-Path $env:TEMP 'YingKu-development-ui.ini'
.\.venv\Scripts\python.exe .\windows_entry.py
```

该路径还会派生普通模式目录和共享搜索设置，退出当前 PowerShell 后环境变量不会保留。`scripts/run_tests.py` 自动设置临时数据与界面配置、关闭启动联网任务，不读取个人影片。

## 依赖与打包

`requirements-windows-lock.txt` 固定本次 Windows 构建依赖。Windows UI 固定 PySide6 6.8.3；Mac 使用另一个平台锁文件。更换 Qt 时须验证网络图片、定时器、窗口布局和打包启动。

`生成Windows运行版.bat` 默认先运行测试，再调用 `scripts/build_windows_icon.py` 与 `YingKu-Windows.spec`。使用项目内 Python 调用 PyInstaller，不自动选择 Mac spec。Windows exe 用 Windows Python 和 Windows 原生依赖打包；不能把 Mac `.app` 改名为 exe。

生成文件位于 `dist/影库`。分发时整目录复制或压缩，不只分发 exe。代码变更后先更新 `VERSION`，检查 exe 文件属性中的产品版本，再验证独立资料库启动和退出。持续集成模板位于 `.github/workflows/windows-build.yml`，可在你自己的仓库手动运行。

## 调试与交接

源码直接用 `python.exe windows_entry.py` 启动可查看输出。运行版意外启动失败时，会写入 `%LOCALAPPDATA%\YingKu\startup-error.log`。网络资料不足或图片限流按既有缓存和回退处理。

下次交接请提供：完整源码、VERSION、锁定依赖、复现步骤、失败日志和对应测试结果；不要将私人资料库或 API 密钥直接提交到仓库。生物识别须在真实 Windows 电脑及对应硬件上核对，兼容层或 CI 的模拟结果不能证明真实指纹/面容体验。
